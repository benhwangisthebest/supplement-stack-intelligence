## daily-checkin (v10)
Closes the platform's open recommendation loop with a **gamified daily check-in + feedback loop**. A daily check-in captures **adherence** (which stack items were taken) + a **1–5 rating on active goals**; a pure `lib/checkin` engine derives a **consistency** metric (premium heatmap, no points/badges), **correlational** outcome aggregates (avg goal rating on taken-vs-not days), and a **bounded, min-sample-gated feedback signal** that nudges the existing `generateProtocol` ranking. Architecture is **additive** with a key safety decision: the feedback signal is inserted as a ranking key **strictly below grade** (`labSignal → grade → feedback → composite → name`), so self-reported feedback is **evidence-subordinate by construction** — it can only break ties within an equal grade and can **never override evidence**. This is *proven, not asserted*: a **no-feedback regression test** shows `generateProtocol` output is byte-identical without a signal, and that a max feedback never lifts a lower grade above a higher one. Consistency also feeds the **v9 identity** `dataDepth`, unifying the two gamification features. All outcome/side-effect copy is **correlational + non-diagnostic** (honesty sweep); the side-effect/note field is **display-only**. Built via Plan-Plus → PDCA (Do ×3 modules, Check **99%**, **0 iterations**, QA **PASS**). Success criteria **10/10**; **340/340 unit** (+29) incl. feedback-regression + honesty; `next build` OK; L1 auth-guard 2/2 + L2 `/stack-lab` redirect 1/1 runtime-verified live, authed L3 env-gated (`E2E_LIVE`, needs `0006` applied). First milestone to intentionally break the no-migration / no-engine-edit streaks — done via **one additive migration** (`0006_checkins`, RLS + unique(user,date)) and **optional, backward-compatible** engine inputs, keeping all prior v3/v4/v5/v9 suites green. No new dependencies. **Deferred to v11:** proactive advisor change-proposals, side-effect engine, reminders/notifications, wearable import, longitudinal trend charts, authed live-E2E provisioning.

## side-effect-engine (v11)
Deepens the safety layer by turning v10's **display-only side-effect note** into a real, engine-backed **correlational** capability. A pure `lib/side-effects` engine — structural sibling to v2 `interactions` and v3 `biomarkers` (`index.ts` engine + `to-flags.ts` → `DraftFlag`) — cross-references a **curated seed** (12 supplements / 27 commonly-reported effects, each with a frequency tier + non-causal `watchNote`) against **structured, canonical user reports**. A **controlled vocabulary** (`SIDE_EFFECT_VOCAB`, 18 labels + alias resolution) is the join key: free text normalizes server-side or is **rejected (400)**, so a non-canonical string can never fabricate a correlation. `reportedDays` is a **true co-occurrence** — the set intersection of report dates ∩ the days v10 adherence recorded the supplement as **taken** — double-gated by `MIN_REPORTS` (3 co-occurring days) and `MIN_TAKEN_DAYS` (5-day adherence sample). Flags are `warning`/`info` only, **never `critical`**, never reorder, and **never feed protocol ranking** (evidence supremacy stays trivially intact — proven by a no-signal regression showing `evaluateStack` output is byte-identical without side-effect data). Surfaces: Library **"What to watch"** (public, empty-state-correct), Stack Evaluation caution, Profile **SVG timeline** (reuses the v4 `TrendChart`), and a 7th read-only **advisor tool** (`sideEffectWatch`, refuse-when-empty). Architecture **Option C (additive)** — **0 existing engines rewritten**, one additive `0007_side_effects.sql` (RLS, `unique(user,date,effect_label)`; v10 `checkins` untouched), **no new dependencies**. Built via Plan-Plus → PDCA (Do ×3 modules, Check **88% → Act-1 → 99%**, QA **CONDITIONAL PASS** → Act-2). Success criteria **8/8**; **388/388 unit** (+48); `next build` OK; full e2e **41 passed / 0 failed**.

> **This cycle's real lesson — two bug classes a green suite cannot see.** 385 tests passed, `tsc` was clean, and `next build` succeeded **while two Criticals shipped**. (1) **G1**: the evaluation copy claimed *"you logged X on N days when you also logged taking Y"* — a co-occurrence the engine never computed; the sentence was hedged, non-causal and banned-phrase-free, and **false**. The honesty sweep validates *vocabulary, not truth*. (2) **G6**: `services/evaluation.ts` never passed the reports into `evaluateStack`, so the flagship surface was **dead code for every real user** — invisible because all 385 tests called the engine *directly* and both context fields are *optional*, so the compiler can never catch omission. Act-1 fixed both; QA then proved by **mutation test** that G6 still had **no regression guard** (the analysis had *recommended* one and shipped without it). Act-2 added `services/evaluation.test.ts` and mutation-verified it goes red on the reintroduced bug. Permanent guards now in place: a **copy↔computation binding** suite (every rendered number must be an engine-computed fact) and a **reachability** suite (every rule must be reachable from its production caller).

> **Honest scope of the 99%.** It is **static + public-surface** confidence only. The configured Supabase project (`cyjofigf…`) returns **NXDOMAIN** — the backend is gone — so v11's **authed half (capture → persist → correlate → timeline, `0007` RLS, the normalization 400) has never executed against a live database in any phase**. This is a genuine gap, *not* the `E2E_LIVE` env-gating convention v4/v10 used: those ran live at least once, against a project that no longer exists. Check-2's "Runtime 99% / 5-5 runnable e2e" excluded the two authed tests that mattered most, and its "prior suites green" was asserted from a partial run — QA caught both. **Deferred to v13:** restore Supabase + apply `0001`–`0007` + seed → clear the authed gap; seed side-effect literature → citation chips (removed from the design in Act-1 rather than fabricate provenance, gap G3); dechallenge/rechallenge + onset-window (causal-inference territory); extend copy↔computation binding to v10/v1 copy (same bug class likely present).

## food-pairings (v12)
Answers the everyday question the Library never addressed: **what should I eat with this?** A curated **supplement↔food** dataset delivers absorption-focused guidance — *pairs well with* (vitamin D + a fat-containing meal, creatine + carbohydrates, curcumin-style synergies) and *best to space apart* (zinc + phytates/calcium, caffeine + caffeinated drinks) — each with mechanism, timing, and an evidence grade. Architecture **Option C (pragmatic)**: rather than build a parallel domain, the feature **extends the existing interactions engine** with a `supplement-food` kind + `direction` (`synergy`/`avoid`), so guidance rides the established `findInteractions → InteractionFinding → to-flags → DraftFlag` pipeline and reaches **Library + Stack Lab + advisor with zero caller changes** (`ALL_INTERACTION_RULES` becomes the engine default). The load-bearing risk defense is **tone**: reusing a model literally named `InteractionRule` for *beneficial* pairings risked rendering "pairs well with citrus" as an alarm — so synergy is pinned to `info` by an explicit guard in `mapSeverity` and given its own `safetyCopy.foodSynergy` + dedicated `FoodPairingSection` UI, both **test-enforced** ("never escalates food guidance to critical"). Built via Plan-Plus → PDCA (Do ×4 modules, Check **99.5%**, **0 iterations**). Success criteria **2/4 met, 2/4 partial, 0 unmet**; **374/374 unit** (+15) incl. schema/integrity/banned-language sweep; **runtime-verified across all 15 catalog pages** (9 with data, 6 graceful empty state). **No migration, no new dependency** — seed-as-code only.

**Honest caveats:** (1) SC-2 partial — coverage is 9/15 supplements, per the curation rule that only well-documented pairings ship and absence never implies "no effect". (2) SC-4 partial — making `ALL_INTERACTION_RULES` the engine default **changed what Stack Lab emits** (a lone berberine now yields a food info flag where it previously yielded none), requiring **6 existing tests** to be updated (4 scoped to `SEED_INTERACTIONS`, 2 re-asserted on category rather than exact counts); intent preserved but the behavior change warrants human review. (3) QA phase not run. **Deferred:** AI-generated pairings, diet/allergy personalization, quantitative dosing math, meal plans, community data.

## evidence-disclosure (v13)
A **trust-layer integrity fix**, not a new feature — and a correction to the v11 record. `.claude/CLAUDE.md` declares *"The Library is the trust layer of the product,"* yet it rendered **fabricated studies as real**: all 20 entries in `seed-papers.ts` carried `example.org` links, invented-looking metadata, and specific sample sizes, shown under a **"View source ↗"** anchor with **no disclosure anywhere in the UI**. The implementation found the authors were **real researchers with unreliable recalled metadata** (Branch JD's creatine meta-analysis is 2003/IJSNEM, the seed said 2018/JSCR) — *worse* than invention, because it looks checkable. **Root cause: the type compelled it.** `Paper.link: string` was **required** *and* `validation/seed.ts` enforced `z.string().url()` — with no real source, a placeholder was the only way to satisfy both. Architecture **Option C**: **delete** the six provenance fields (`authors`/`journal`/`year`/`link`/`studyType`/`sampleSize`) rather than guard them, so `tsc` enumerates every consumer and fabrication becomes a **type error, not a convention**. Educational content (dose/duration/outcomes/limitations/summary) is preserved; an `IllustrativeDatasetNotice` is mounted on both evidence surfaces; the advisor tool stops emitting recalled provenance; 10 fabricated affiliate links → `null`. Three guards, **each mutation-checked red before being trusted**: **G1** (no `example.org` under `src/`), **G2** (seed objects carry no provenance keys), **G3** (disclosure reachable via the **production render path** across all 15 catalog pages). Built via compact PDCA (plan → design → do ×3 → check). Success criteria **8/8**; **392/392 unit** (+22 guards); `next build` OK (Library still SSG ×15); full live suite **79 passed / 10 failed = the pre-existing baseline, zero regressions**.

> **Two lessons.** (1) *Delete the field, don't guard it* — the fabrication's root cause was a **required** field; removing it made the compiler prove coverage. But `validation/seed.ts` was a **second** required-URL declaration the design's file list **missed** — invisible to `tsc` (Zod is a runtime structure), caught only by the test suite. Same v12-L1 shape (a shared change with an unenumerated caller) recurring in the very cycle whose author cited L1; recorded as a real design-accuracy dock rather than papered to 100%. (2) This cycle also **corrected the v11 record**: the Supabase backend is **alive**, all 7 migrations applied, and v11's "never verified authed" claim was false — re-verified live (`61→79` suite). The prior memory's "NXDOMAIN / backend gone" was wrong.

> **Scope held: disclosure only, not grounding.** The adjacent defect — **19/27 effect grades are hand-typed literals** with no `evidenceProfile`, some Grade-A on a single (now provenance-free) summary — was **deliberately deferred**. Grounding first would have dressed ungrounded claims in fabricated citations; disclosure-first **unblocks** a future grounding cycle that must use **real verified DOI/PMID** literature. Also deferred: `context-adjusted-evidence` (v13's original subject, halted at design — personalization would *amplify* fabricated provenance; plan needs revision, incl. its false assumption of a `populationRelevance` seam that exists for only 8/27 effects).
